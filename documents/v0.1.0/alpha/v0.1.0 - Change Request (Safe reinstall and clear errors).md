# v0.1.0 - Change Request (Safe reinstall and clear errors)

## 1. Summary
Two developers could not finish the one-command setup:

| Machine | What they saw | Cause |
|---|---|---|
| macOS (Elsa) | `Installed .` then `Killed: 9` on `gita profiles --json`, "Couldn't add the Gita profile" | macOS killed the `gita` program. `install.sh` copies the new `gita` *over* the old `~/.gita/bin/gita` with `cp -R`. macOS keeps the old file's code signature cached, so the overwritten file no longer matches and the kernel kills it. The script never checked that Gita runs after installing it. |
| Windows (Thomas) | "GitHub says this project doesn't exist, or ThoughtBox AI (@thomas2201-sunil)'s account can't see it" when cloning claude-standards | The sign-in saved for the "ThoughtBox AI" (@thoughtbox.one) profile belongs to his @thoughtbox.io GitHub account (`@thomas2201-sunil`; Gita records the account a token belongs to when it signs in). This run signed in correctly in the browser, but the installer skipped the sign-in: it treats "a token exists" as "signed in", so an earlier .io sign-in was reused. That account isn't in ThoughtBoxFinTechAI, so GitHub answers "not found". (A global `insteadOf` rule sending github.com to SSH with the .io key would give the same error; the clean-up in item 12 covers that too.) |

This change makes both installers check the real state of every step before acting —
installed, wrong version, broken, running, half-done — and fix it (remove, reinstall,
retry) or stop with a message that says exactly what to do.

## 2. Scope
In scope (`install.sh` for macOS/Linux and `install.ps1` for Windows, same behaviour):
1. **Gita install states:** not installed → install; right version and runs → skip;
   wrong version → reinstall; installed but won't run (killed, corrupt, missing library)
   → remove and reinstall.
2. **Replace, never overwrite:** old `~/.gita/bin` and `~/.gita/lib` are removed before
   the new files go in (fixes `Killed: 9`). Only `bin` and `lib` are touched; profiles and
   settings in `~/.gita` are kept.
3. **Check after install:** `gita --version` must print the pinned version. On macOS, if
   it is killed, re-sign it locally (`codesign --force --sign -`) and try once more. Then
   stop with a clear message if it still fails.
4. **Gita running:** Windows can't replace a running `gita.exe` (the app, or Claude Code
   running `gita mcp`). Detect Gita processes from both the app folder and `~/.gita/bin`
   and ask the developer to close Gita and Claude Code. macOS/Linux: ask to close the
   Gita app before replacing it.
5. **Prerequisites:** a tool counts as installed only if it actually runs (`--version`),
   not just if it is on PATH. After installing one, check again; stop clearly if it still
   isn't usable.
6. **Downloads:** timeouts and retries on every download (`curl --connect-timeout
   --max-time --retry`, `Invoke-WebRequest -TimeoutSec`), clear message on failure.
7. **Profiles:** if `gita profiles` fails, say so plainly (instead of a raw crash).
   Show which GitHub account each profile is signed in as, so a wrong account is visible.
8. **Clone of claude-standards:**
   - Folder exists and is the right repo → update it (`git pull --ff-only`) if it has
     no local changes; otherwise keep it and say so.
   - Folder exists but is empty, not a git repo, or a different repo → move it aside to
     `claude-standards.backup-<time>` (never deleted) and clone again.
   - Clone fails → explain the likely causes (organisation hasn't approved Gita; signed
     in with the wrong account) with the exact steps, and offer to sign in again and retry
     once.
9. **Every other step** (company import, claude-standards setup, `gita mcp
   add-to-claude`, `gita doctor`): a failure names the step, the likely cause and what to
   do. `gita doctor` problems are reported as such, not followed by "Done.".
10. **End summary:** a short table of each step: done / already done / skipped / failed.
11. **Log file:** every run writes a log (`~/.thoughtbox-setup.log`, the last run only),
    so a developer can send it when asking for help. It holds command output only; no
    tokens are printed by any step.
12. **Clean-up of old GitHub sign-ins and git settings ("cleanse"), before the accounts
    step.** A machine that was used with another GitHub account can send that account to
    GitHub instead of the Gita one. The installer looks for each item below, lists what
    it found, and asks once before removing them (`TB_CLEAN=1` answers yes; a dry run only
    lists). `~/.gitconfig` is backed up first.

    | Found | Why it can pick the old account | Action |
    |---|---|---|
    | `url.*.insteadOf` rules for github.com in global git config | Turns `https://github.com/...` into SSH, so the old account's SSH key is used and Gita's sign-in is skipped | Remove |
    | `http.https://github.com.extraHeader` (an `Authorization` header) | Sends a fixed old token with every request | Remove |
    | github.com credential helpers in global git config (`!gh auth git-credential`, `manager`, `osxkeychain`, `store` scoped to github.com) | Gita already switches these off for its own commands, but plain `git` outside Gita still uses the old login | Remove the github.com-scoped entries only; a general `credential.helper` for other hosts stays |
    | Saved github.com logins in the system store (Windows Credential Manager, macOS Keychain, libsecret, `~/.git-credentials`) | Old token used by plain `git` and by Git Credential Manager pop-ups | Erase the github.com entries (`git credential reject`) |
    | GitHub CLI logins (`gh auth status`) | `gh` (used by Claude for PRs) acts as the old account | Log out each github.com account (`gh auth logout`); the developer signs in again with `gh auth login` later if they use it |
    | `GH_TOKEN` / `GITHUB_TOKEN` set in the user environment | `gh` and other tools use the old token | Windows: remove from the user environment after asking; macOS/Linux: say which rc file sets it (not edited) |
    | `~/.ssh/config` `Host github.com` with a key | Only matters for SSH remotes | Report only (not changed) |

    Never touched: Gita's own profiles and tokens, other hosts' logins, SSH keys.
13. **Catch a sign-in with the wrong account.** This is what happened on Thomas's
    machine: an older sign-in of the "ThoughtBox AI" (@thoughtbox.one) profile belonged to
    his @thoughtbox.io GitHub account, and the installer reused it because it only checks
    that a token exists.
    - **"Already signed in" means the right account, not just a token:** when a profile
      already has a sign-in, the installer shows its GitHub login and asks to keep it. A
      "no", or the checks below, run the sign-in again, which replaces the old token.
    - **Automatic check:** if both profiles are signed in as the same GitHub login, at
      least one is wrong. The installer says which login is on both and signs the
      @thoughtbox.one profile in again (or the .io one, if that is the one that changed).
    - **Before cloning claude-standards:** if the clone fails, the message names the login
      the "ThoughtBox AI" profile is signed in as and says it must be the account in
      ThoughtBoxFinTechAI, then offers to sign in again and retry once.
    - **Confirm prompt:** after each Gita sign-in the installer shows
    "Signed in as @login — is that your GitHub account for <email>?" If not, it removes
    that sign-in by running the sign-in again (a new sign-in replaces the token), reminding the developer to sign out of the
    other account in the browser first (the GitHub code page signs in whoever is logged in
    there).

Out of scope:
- Signing and notarising the Gita macOS release (that is a change in the `gita` repo;
  listed as a suggestion).
- Approving the Gita OAuth app in the GitHub organisation (an org owner does that in
  GitHub settings; the installer only explains it).
- Changes to Gita itself or to claude-standards' own `setup.sh`/`setup.ps1`.
- An uninstall command.

## 4. Design decisions
- **D1 Replace, don't overwrite.** Delete the old files first, then copy. This is the
  documented way to avoid macOS's cached-signature kill, and it also clears stale
  libraries on every OS.
- **D2 Ad-hoc re-sign only as a fallback.** Gita's CI already verifies the signature; the
  re-sign runs only if the installed program is killed, so a good build stays untouched.
- **D3 Never delete user data.** A wrong or broken `claude-standards` folder is moved
  aside with a timestamp, not deleted. `~/.gita` profile data is never removed.
- **D4 One retry, then stop.** Clone and sign-in get one guided retry; endless loops hide
  the real problem.
- **D5 Errors name the step and the fix.** Each failure prints: what failed, the likely
  cause, the next action, and where the log is. Details go to the log.
- **D7 Clean-up asks once, backs up, and only removes github.com items.** It lists
  everything it found and asks one yes/no, so a developer sees what will change.
  Non-GitHub logins and SSH keys are left alone because other work may depend on them.
  Note: Gita's own clone already turns off other credential helpers for github.com, so a
  cached login alone shouldn't break the clone; an `insteadOf` rewrite to SSH or a
  sign-in done in a browser logged in as the old account would. The clean-up plus the
  account check (item 13) covers all of these.
- **D6 Same behaviour on both scripts.** Every item in §2 is in both, checked off in §8.

## 5. Security checklist
- [x] Downloads still checked against the pinned SHA-256 before anything is installed
  (tested with the real v1.0.2 downloads on Linux and Windows).
- [x] TLS only (`--proto =https --tlsv1.2`; TLS 1.2 on Windows); timeouts on every
  network call (curl timeouts and retries, `Invoke-WebRequest -TimeoutSec`, git
  `lowSpeedLimit`, SSH `BatchMode`/`ConnectTimeout`, a 180 s cap on `git pull`).
- [x] No token or secret is printed or logged. Tested: planted tokens never reached the
  screen or the log. One exception to "never on the command line": an old `insteadOf`
  rule whose *name* holds a token (`url.https://user:token@github.com/.insteadOf`) can
  only be removed by passing that name to `git config --unset-all`. It is never printed
  (shown as `//***@`) and is gone after the run.
- [x] Git's answer to `git credential fill` (it may hold a password) is discarded: to
  `/dev/null` on macOS/Linux, to `NUL` on Windows.
- [x] Log file is created with owner-only permissions (`chmod 600` / user-only ACL), checked
  on both. The `~/.gitconfig` backup is owner-only on macOS/Linux (umask 077); on Windows it
  inherits the home folder's permissions, which are user-only by default.
- [x] Ad-hoc re-sign only touches `~/.gita/bin/gita`, only after the checksum passed.
- [x] Moving folders aside never follows a path outside `$HOME` (only `~/claude-standards`
  is moved, to a name next to it).
- [ ] `shellcheck`: **not run** (not installed on this machine). `bash -n` and the
  PowerShell parser are clean.
